📖 演示指南 — 五幕叙事

点击展开

第一幕 · Setup — 5 片晶圆 Lot 进入 Fab。设备空闲，等待 Pipeline 启动。

第二幕 · Normal — FOUP 沿 STOCKER → LITHO → CDSEM 流转。晶圆加工、CD 值量测。时间线绿色推进。

第三幕 · Chaos — 设备随机故障（~20% 概率）。故障事件出现在日志中。Recovery Status 徽章变红。

第四幕 · Self-Healing — OCAP 规则引擎评估故障条件并执行动作（Rework / Scrap / Notify / AdjustRecipe）。崩溃的 Actor 通过 Event Sourcing Journal 重放恢复——已完成阶段自动跳过（断点续传），从中断处继续执行。

第五幕 · Resolution — 所有晶圆完成加工。统计面板显示 Pass/Scrap 计数、故障处理次数、恢复成功次数。

⚡ 单 WorkOrder 自愈机制：FabPipelineExecutionActor 是 EventSourcedBehavior——崩溃后 Akka Persistence 重放事件恢复状态，RecoveryCompleted 信号中调用 resumeFromIndex 从断点继续。已完成阶段（completedPhases cursor）持久化在事件日志中，恢复时直接跳过，避免重复执行。

⚠ 已知边界：多 WorkOrder 并发场景下，若崩溃注入命中 Idle 状态的 Actor（StartExecution 尚未处理），消息丢失后缺乏上层编排聚合重试——需要后续引入 WorkOrderBatch 聚合或 Watchdog 机制。

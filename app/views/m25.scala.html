二、M2.5+ 解法：标准组件库

将技术复杂性和业务变化分离。技术复杂性封装为标准组件（一次编写、独立测试、统一修复点）； 业务变化通过参数注入组件实例（不生成代码、不修改状态机）。

一条业务链路的处理流程——每个方框是一个独立可替换的标准组件
BatchMaster → fan-out → SubBatch ×N
↓
SubBatchProcessor → ResultClassifier → 三分类分流
成功项 → 继续后续 可疑项 → ReconfirmHandler 失败项 → ReBatchRouter
↓ 按目标设备区分组
AreaScheduler → 重新成批分派 → ...下一工序...

六大标准组件

⚙️
技术组件

SubBatchProcessor

处理一个小批次与外部系统的完整交互周期：文件生成 → 上传 → 等待确认 → 轮询响应 → 解析 → 分类。同一套处理器可用于充值、申购、Fab 光刻——区别仅在于注入的 Pipeline 配置不同。

🏷️
业务参数

ResultClassifier

将外部系统返回结果按业务规则分为成功 / 失败 / 可疑三类。通过 ErrorCodeMapping（成功码集合、失败码映射、可疑码集合）进行参数化。充值、申购、光刻量测各用不同的映射表，同一分类器。

🔍
技术组件

ReconfirmHandler

仅对分类为"可疑"的项执行复核（通过 Core API 二次查证、重新量测等），确定最终是成功还是失败。不是流水线的必经阶段——成功和失败项不经过这里。

🧠
业务参数

ReBatchRouter

智能决策——根据失败原因决定下一步：在同一设备区重试？换设备区？换配方？报废？生成人工工单？通过 ReBatchPolicy（错误码 → 动作映射）参数化。M2 的"重新注入 Worker"只是多种决策之一。

📦
物理约束

AreaScheduler

接收上游 items，考虑物理约束（FOUP 容量、最小/最大批次大小、时间窗口、是否允许混批）重新成批，分派到设备。薪资存入场景约束宽松（1–100 笔），Fab 约束严格（FOUP 25 片、同 recipe 混批）。

🔌
基础设施

Connector + Encoding

HTTP / SFTP / SMS 连接器，内建断路器 + 重试 + 超时。编码策略（JSON / XML / CSV / 加密文件）与连接器解耦。与 Saga 无关——可被 SubBatchProcessor 直接调用。

关键设计决策：组件库 vs 模板生成。 模板在编译期展开为 FSM 代码——修 bug 需要改模板、重新生成。 组件库在运行期按参数实例化——修 bug 改一次组件，所有实例自动继承修复。 两者都保持编译时类型安全（组件接口由 trait 约束，参数由 case class 约束）。

三、业务参数化：同一套组件，不同配置

M2.5+ 的核心价值不在于"消除了多少行代码"，而在于修改的爆炸半径。 产品经理关心的参数（错误码映射、失败处理策略、批次大小）从代码深处提升到配置层。

四、M3 愿景：同一套组件，动态工序编排

M3 面向半导体 Fab 的动态工序编排。9 个设备区 + 物流指挥系统 = 10 个需连接控制的外部系统。 它们全部共享 M2.5+ 的同一套组件——SubBatchProcessor、ResultClassifier、ReBatchRouter、AreaScheduler。 唯一的区别：工序序列不是静态代码，而是从产品工艺路线数据库在运行时加载。

M3 特有：三个新增能力

🗺️

ProductRouting · 动态工艺路线

工序序列从数据库加载，而非硬编码在代码中。产品 LOGIC-28NM-A 可能走 11 道工序（含 Lithography 重入），NAND-96L-A 走 13 道（含 Deposition/Etch 4 次循环）。工艺变更时更新数据库即可，不需要改代码。

📦

BatchMergeManager · 合批入库

原始 Lot（25 片）在加工过程中可能被拆散——部分片 rework 去了别的设备区、部分片报废。入库时，追踪原始 Lot 归属，所有合格片完成后自动触发合批。这是 Fab 区别于薪资存入的物理约束。

🔄

Reentry Tracking · 重入追踪

同一设备区可能被访问多次（光刻的多重曝光、3D NAND 的沉积刻蚀循环）。reentryIndex 追踪第几次访问，确保每次使用正确的 recipe 和设备状态。

架构师视角——为什么不需要新的执行引擎。 M2.5+ 的 SubBatchProcessor、AreaScheduler、ReBatchRouter 已经覆盖了"工序执行的完整生命周期"。 M3 的变化在工序序列的来源——从编译时确定的静态配置变为运行时加载的动态工艺路线。 SagaTransactionCoordinator 不需要改动；StepExecutor 的断路器/重试/超时不需要改动；Connector 不需要改动。 唯一新增的是 ProductRouting（数据模型）+ BatchMergeManager（Fab 物理约束）+ FabFlowEngine（动态组装）。

二、M2.5+ 解法：三层分离架构

M2.5+ 将系统划分为三个正交维度——业务维度定义步骤序列与批次管理、 技术维度封装通信协议栈与容错组件、业务调度维度标准化结果分流与异常处理。 每个维度独立演进、独立测试、独立修复，组合起来覆盖完整的跨系统编排生命周期。

工单 → 批次管理器拆批 → 单批次工序序列管理器推进步骤 → 业务步骤链执行 → 技术组件支撑远程通信 → 批量结果散射器三路分流 → 异常调度 / 再确认

三层维度组件

业务维度 · 步骤管理与执行

📋
批次管理

批次管理器

将工单拆分为多个批次生产，管理批次生命周期。每个批次包含 ×2000 制造单元，独立推进业务步骤序列。

🔀
步骤推进

单批次工序序列管理器

管理当前批次所在的业务步骤，推进/回退步骤序列。5 个标准步骤模板：① 额度资源锁定 → ② 批量充值 → ③ 批量申购 → ④ 结果批量通知 → ⑤ 额度资源解锁。每步骤 4 个标准工序：请求发起 → 收集结果 → 结果散射 → 结果再确认（全部异步、事件驱动）。

技术维度 · 标准化可复用组件

📦
物理约束

出站缓冲 · 重新成批

按物理约束（FOUP 容量、时间窗口、同 recipe 混批策略）重新成批后分派到设备。薪资场景约束宽松（1–100 笔），Fab 场景约束严格（FOUP 25 片）。

⚡
容错

断路器

内建重试 · 超时 · 熔断 · 恢复机制。所有外部通信统一经过断路器保护，故障隔离不扩散。

🔄
格式

编解码

JSON / XML / CSV / 加密文件格式转换，编码策略与连接器解耦。新增报文格式只需实现 Codec 接口。

🔒
安全

安全加密

传输层 TLS / 应用层 AES / 国密 SM4。加密策略参数化，按外部系统安全等级自动选择。

🔌
通信

通信协议栈

SFTP / HTTP-XML / HTTP-JSON 多协议适配。新增传输协议只需实现 Connector 接口，不影响上层业务逻辑。

业务调度维度 · 结果分流与异常处理

🎯
分流

批量结果散射器

对每个制造单元的远程通信结果进行三路分流：✅ 成功 → 继续下一个业务步骤；❌ 失败 → 上报异常调度器；⚠️ 可疑 → 发送再确认组件。全部异步事件驱动。

🚨
异常

异常调度器

接收散射器上报的失败结果，经过缓冲（空间约束）与超时（事件约束）后发出向前补偿请求到批次管理器，重新指定业务步骤（补偿/跳过/终止）。

🔍
复核

再确认组件

对可疑结果进行二次查证（通过更高精度量测、Core API 核验或人工复核），确定最终成功/失败后回传散射器。不是流水线的必经阶段——成功和失败项不经过这里。

关键设计决策：三层分离 vs 单体 FSM。 业务维度定义"做什么"（步骤序列），技术维度提供"怎么做"（通信/容错/加密），调度维度决定"结果去哪"（成功推进/失败补偿/可疑复核）。 三层分离意味着：业务人员修改步骤序列不需碰技术组件；基础设施团队升级断路器不需理解业务逻辑；调度策略变更（如"可疑阈值从 5% 调至 3%"）是参数配置而非代码修改。 区别于 M2 的模板生成：组件在运行期按参数实例化——修 bug 改一次组件，所有实例自动继承修复。

三、业务参数化：三个维度，各自配置

M2.5+ 的核心价值不在于"消除了多少行代码"，而在于修改的爆炸半径。 三个维度的参数各自独立：业务维度配置步骤序列与批次约束，技术维度配置协议/重试/加密策略，调度维度配置分流规则与补偿策略。 产品经理关心的参数从代码深处提升到配置层，每个维度独立变更、独立验证。

四、M3 愿景：同一套组件，动态工序编排

M3 面向半导体 Fab 的动态工序编排。9 个设备区 + 物流指挥系统 = 10 个需连接控制的外部系统。 它们全部复用 M2.5+ 的三层分离架构——业务步骤链、技术组件栈、调度分流器无需改动。 唯一的区别：工序序列不是静态代码，而是从产品工艺路线数据库在运行时加载。

M3 特有：三个新增能力

🗺️

ProductRouting · 动态工艺路线

工序序列从数据库加载，而非硬编码在代码中。产品 LOGIC-28NM-A 可能走 11 道工序（含 Lithography 重入），NAND-96L-A 走 13 道（含 Deposition/Etch 4 次循环）。工艺变更时更新数据库即可，不需要改代码。

📦

BatchMergeManager · 合批入库

原始 Lot（25 片）在加工过程中可能被拆散——部分片 rework 去了别的设备区、部分片报废。入库时，追踪原始 Lot 归属，所有合格片完成后自动触发合批。这是 Fab 区别于薪资存入的物理约束。

🔄

Reentry Tracking · 重入追踪

同一设备区可能被访问多次（光刻的多重曝光、3D NAND 的沉积刻蚀循环）。reentryIndex 追踪第几次访问，确保每次使用正确的 recipe 和设备状态。

架构师视角——为什么不需要新的执行引擎。 M2.5+ 的业务步骤链、技术组件栈、调度分流器已经覆盖了"工序执行的完整生命周期"。 M3 的变化在工序序列的来源——从编译时确定的静态配置变为运行时加载的动态工艺路线。 SagaTransactionCoordinator 不需要改动；StepExecutor 的断路器/重试/超时不需要改动；Connector 不需要改动。 唯一新增的是 ProductRouting（数据模型）+ BatchMergeManager（Fab 物理约束）+ FabFlowEngine（动态组装）。

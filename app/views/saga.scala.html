一、为什么需要 Saga

在微服务和 CQRS/ES 架构中，数据分散在多个聚合根和外部系统之间。传统的 2PC（两阶段提交） 依赖数据库锁和事务管理器，在分布式场景下存在致命缺陷：锁定时间长、单点故障、 不兼容异构数据源。Saga 通过将全局事务拆分为一系列本地事务，每个步骤独立执行与补偿， 实现了无锁的分布式一致性。

核心洞察：在 Fab 场景中，一个 Lot Start 涉及的 158 万行记录中绝大多数是下游数据（历史快照、审计追踪、交叉引用）。 Saga 不必等到"所有东西都写完"才提交——当前操作先完成，下游数据通过事件异步写入。 一致性边界从"整个操作"缩小到"当前步骤"，这是吞吐量提升的根源。

二、架构全景：三层编排模型

M1 Saga 采用编排器驱动（Orchestrator-Driven）模式。Saga 不再是抽象概念， 而是一个独立的基础设施层（saga-core），业务层只需实现 Participant 接口。

业务层（Facade + Participant）→ 编排引擎层（Coordinator + StepExecutor）→ 基础设施层（Persistence + Sharding）

模块独立性：Saga 编排引擎是独立库（saga-core/），零业务依赖。业务层（app/）通过依赖注入绑定 Participant 实现。 这意味着一套 Saga 引擎可以驱动任何分布式事务场景——转账、Fab Lot Start、跨系统数据对齐—— 只需要提供不同的 Participant 实现。

三、TCC 三阶段模型

M1 Saga 采用 Try-Confirm/Cancel (TCC) 模式。每个步骤不直接执行操作，而是分三阶段进行。 步骤可分组并行执行（同一 group 内的步骤并发）。

🔒

Prepare（预留）

检查前置条件，预留资源，但不提交。例如：检查余额是否充足、锁定 FOUP 槽位。 如果任何步骤 Prepare 失败 → 触发向后补偿，只补偿已 Prepare 成功的步骤。 Prepare 阶段对应可回滚的操作。

✅

Commit（确认）

确认执行操作，数据真正持久化。例如：实际扣款、写入状态表。 所有步骤 Prepare 成功后，进入 Commit 阶段。Commit 失败同样触发补偿—— 只有 Commit 成功的步骤需要补偿。Commit 对应不可回滚但可补偿的操作。

↩️

Compensate（补偿）

撤销已完成步骤的业务影响，不是数据库 ROLLBACK。例如：退款、释放锁定槽位。 补偿本身可能失败——此时 Saga 不是死锁，而是进入 SUSPENDED 状态， 等待人工介入：ManualFixStep + RetryCurrentPhase。

分组并行：相同 group（stepGroup）的步骤并发执行，不同 group 串行。 一个组内所有步骤 Prepare 成功后，统一进入 Commit 阶段。 这保证了组内并行、组间有序的执行语义。

五、Backward Recovery 机制

当 Prepare 或 Commit 阶段有步骤失败时，Saga 不往前推进，而是向后补偿—— 只补偿已经成功完成当前阶段的步骤。这种方式保证了：

🎯

精确补偿范围

Coordinator 维护 successfulSteps 集合——只跟踪在当前阶段（Prepare/Commit/Compensate）成功的步骤。 补偿只针对这个集合中的步骤，不会重复补偿或遗漏补偿。

⚡

并发执行与停止

Coordinator 发现失败后，先停止所有尚未完成的子 StepExecutor， 然后对 successfulSteps 中的步骤逐一发起 Compensate。补偿过程可以并行。

🔄

幂等恢复

StepExecutor 在 Succeed 状态下收到 Start 命令时，直接返回缓存的执行结果， 不重新执行——避免了重复扣款、重复发货等问题。这项保证在节点重启恢复时同样有效。

Backward Recovery 的核心逻辑：只补偿已成功的步骤，补偿失败则挂起（SUSPENDED）， 直到人工确认或系统恢复。这与数据库的 ROLLBACK 不同——Saga 的补偿是一次新的业务操作， 它本身也可能失败，因此需要 SUSPENDED 机制兜底。

六、模块结构与代码参考

M1 Saga 代码分布在两个模块：saga-core（独立引擎库）和 app（业务集成）。

文件模块职责

saga-core/.../StepExecutor.scala引擎步骤执行器——每个步骤对应一个子 Actor，处理 Prepare/Commit/Compensate
saga-core/.../SagaParticipant.scala引擎参与者接口——doPrepare / doCommit / doCompensate + 错误分类
saga-core/.../ExecutionPlan.scala引擎执行计划——预计算阶段分组，按 group 组织并行/串行

app/protobuf/saga_v2.proto序列化Saga 核心协议定义——Coordinator + StepExecutor 事件
app/protobuf/saga_participant.proto序列化业务参与者协议——FromAccount / ToAccount 事件

Protobuf 三件套规则：修改 Saga 相关的任何数据结构时，必须同步更新 (1) Scala Case Class、(2) .proto 文件、(3) Proto Converter (toProto/fromProto)。三者不一致会导致序列化失败。
